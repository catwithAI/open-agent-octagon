# Wire 通信观测

Wire 是 OpenAgentOctagon 的通信观测子系统：在不改动被测 agent 的前提下，采集 agent 与
模型/工具之间的通信，归一化成统一的 canonical 记录，供对比分析。它是框架的一个亮点，
但也直接触及**敏感数据**——本文说明它采集什么、默认采不采、怎么脱敏、以及使用者该知道的
威胁模型。

> 一句话：**默认只记元数据（大小/时序），不落报文原文；落原文是需要显式开启的高档位，
> 且写盘前强制脱敏。**

---

## 采集档位（capture policy）

Wire 用四个严格递增的档位控制采集深度：

| 档位 | 采集内容 | 用途 |
|---|---|---|
| `off` | 完全不采集 | 关闭观测 |
| `metadata`（**默认**） | 只记 size / timing / 端点等元数据，**不落 payload** | 真实用户任务的默认档 |
| `parsed` | 记结构化解析后的内容（已脱敏） | 需要看调用形状但不需要原始字节 |
| `full` | 落写盘前脱敏的协议原文 | 专用 benchmark，需逐字节复现时显式开启 |

**默认是 `metadata`**：普通运行不会把请求/响应正文落盘。只有显式配置 `parsed` 或 `full`
才会采集内容，且 `full` 应仅用于你明确需要报文原文、且清楚数据边界的专用评测。

档位在 task / run / source 三层求**最严格交集**：任何一层收紧都生效，放宽不能绕过更严的约束。

---

## 写盘前脱敏是硬边界

无论哪个档位，只要采集内容，**secret 必须在进入落盘通道之前被移除**。脱敏管线有三层规则：

1. **Header 黑名单**：`Authorization`、`Cookie` 等敏感 header 的值永不落盘。
2. **JSON key 匹配**：递归匹配 `api_key | token | secret | password | authorization | cookie`
   （大小写不敏感），命中 key 的整个值替换为占位符。
3. **自由文本 secret 形状**：payload 字符串、日志、错误消息里的 `sk-...` / `Bearer ...` /
   AWS key / JWT 等形状一律替换。

**失败即降级，绝不回落原文**：脱敏器自身抛异常时，丢弃该 payload、只保留 metadata 并标记
脱敏失败——不会 fallback 到未脱敏的原始报文。任何可能内嵌请求片段的文本（parse error、
manifest 失败原因等）都要先过同一套脱敏。

---

## 数据生命周期

- 采集到的内容先进 spool（有体积上限，超限的 attempt 会被隔离而不是拖垮进程），
  归一化后写入该 attempt 的 wire 目录（`wire.jsonl` + manifest）。
- wire 数据属于 attempt 的产物，随 attempt 数据一起留存/清理，不会外发。
- 未设内存上限时，异常大的 spool 可能把恢复路径的内存推到危险水平——部署时应配置上限
  （见 `octagon.yaml.example` 的 wire 相关项）。

---

## 威胁模型与使用建议

Wire 的价值在于"看清 agent 到底发了什么、收了什么"，这天然意味着它有能力接触敏感通信。
使用时请注意：

- **默认档位就够日常对比用**：`metadata` 不落正文，绝大多数对比分析（调用次数、时序、
  端点差异）在这一档已经可做。不要为了"看得更多"随手开 `full`。
- **`full` 是 opt-in 的**：只在你需要逐字节复现、且清楚这批任务的数据不含不可落盘的敏感
  信息时开启。开启后即使有脱敏，也应把 wire 产物视作敏感数据管理。
- **脱敏是尽力而为的最后一道闸，不是许可证**：它能挡住常见 secret 形状，但不能替你判断
  "这段业务数据该不该落盘"。数据边界由你在选择档位时决定。
- **被测 agent 不因 Wire 改变行为**：Wire 是旁路观测，`off` 时框架行为与不存在 Wire 完全一致。
