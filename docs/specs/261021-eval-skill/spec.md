## 1. 基线与实施顺序

第一阶段仅接入 `blade-agent`：智能体下拉框保留，唯一选项且默认值为 `blade-agent`。Skill Eval 创建、重跑和比较接口须校验该范围，历史查询仅返回此功能的 Blade 运行；不修改现有平台其他功能的多智能体能力。模型仍从目标 Blade 环境获取，支持跨模型和跨 skill 版本比较。

- 产品需求以本目录 [requirement.md](requirement.md) 为准；UI 与交互批注见 `ui/`。
- 用户指定 Blade 服务：`https://agent.preview.bladeai.com.cn/`。2026-10-21 已读取 `/api/version`，返回 `2612.0.0-beta.41`、`min_sdk=1.1.1`。
- SDK 已固定 `blade-agent-kit==2612.0.0b41`；CLI 从 beta.41 的 `8690d275ddb1e2a760559b10aaf841ba3ca881b2` 构建，安装于当前 worktree 的 `.venv/bin/blade`。服务发布号、SDK 包版本、CLI 构建版本分别保存，不能相互代替。
- 先迁移并验证当前仓库的 Blade 接入层，再实现 Skill Eval 的上传、编辑、运行、历史、比较与备注。不能只修改服务地址或安装新版依赖后继续使用旧协议。
- 本稿记录完整迁移范围，其中基础升级及旧历史命令替换已实施，不代表新 Skill Eval 业务与真实服务执行联调已完成。

已实现：依赖锁、原生 CLI 安装脚本、CLI 历史改由 SDK 获取、版本记录、消息/工具返回 ID 保留、normalizer 来源兼容、历史失败状态及相关 CI 测试。安装与验证见 `docs/agents.md`。现有 CLI 执行通道仍是事后回收，未宣称完成实时订阅组合或 skill 上传业务入口。

## 2. 升级前查明的现状与差异

| 当前实现 | beta.41 基线下的问题 |
| --- | --- |
| `backend/config.py`、`backend/run_dispatch.py` 新任务默认选择 CLI，恢复路径显式使用 SDK | 新功能采用何种执行与观测组合需明确配置，不能只改恢复路径或全局静默切换 |
| `pyproject.toml` 声明 `blade-agent-kit>=1.1.7` | 没有固定测试版；对应 lock 需同步更新，运行时记录实际安装版本 |
| `BladeCliAdapter._chat_run()` 不传 `--skill` | CLI 支持会话级上传，但平台未接入冻结 skill 包 |
| CLI 完成后调用 `blade session history` | beta.41 已移除该命令，当前轨迹回收会失败 |
| CLI 历史投影保留正文与工具调用，却不保留节点 ID、工具返回关联 ID | 无法可靠还原“行动 → 返回 → 模型 react”，需要完整来源与关联信息 |
| Blade normalizer 只处理 `socket`、`messages_poll`，CLI 写入 `blade_cli_history` | 事件写出和读取契约不一致，必须统一或显式适配，不能只改 source 字符串 |
| 现有 SDK adapter 使用 `chat`、历史轮询、恢复与 thinking 事件 | 核对 beta.41 实际签名、事件字段、终态与重放语义；不能因方法名称相同就认定完全兼容 |
| 现有 attempt 输入包含 env、token、回调与评分相关约定 | Skill Eval 不评分，且目标为远程服务，应拆出不要求场景回调的输入协议 |

现有 21 项 CLI adapter 测试已通过，但其 CLI 是桩脚本，包含旧 `session history` 契约；不能作为 beta.41 兼容性证明。

## 3. Blade 接入迁移范围

beta.41 能力边界已按对应标签源码核对：CLI 的 `chat run --skill <目录> --file <本地路径=远端路径> <提示>` 支持先上传完整 skill 和任务物料，再发送提示执行；但当前 CLI 不将模型／工具实时事件流输出给 Octagon。CLI 内部订阅事件并等待终态，不等同于平台能采集完整过程。因而三项需求的完整方案是“CLI 执行 + SDK/API 采集”，或统一使用 SDK 执行与采集；不能把仅升级 CLI 写成全部满足。上传后的 skill 实际使用，以及 reasoning／上下文的可见范围，仍需真实服务样本验证。

### 3.1 依赖、配置与能力检查

- 精确固定 SDK 版本并更新 `uv.lock`；依赖仍按仓库可选 extra 约定管理，是否需要 Blade 应在启动与能力检查时明确报告。
- 配置支持服务地址、鉴权、执行通道与观测能力；预览地址作为本次部署配置，不硬编码为所有用户的默认地址。
- 能力检查区分服务可达、鉴权可用、SDK 版本、CLI 可执行及其构建版本、skill 上传、事件订阅和历史接口。不能仅因存在 API key 就把全能力标为可用。
- CLI 启动前检查本机 OS/架构与可执行性，不能把已有 Linux ARM64 构建直接当作 macOS 可运行程序。

### 3.2 执行与上传

- Skill Eval 优先使用 SDK 创建会话、`upload_session_skill`、上传任务输入后执行 `chat`。该选择为当前讨论方案，实施时单独验证，不直接改掉现有场景的执行方式。
- 如保留 CLI 执行路径，新增 `--skill <冻结目录>` 支持；所有路径、文件与参数通过结构化 argv 传递。
- skill 上传完成后记录远端回执、名称和路径（以接口实际返回为准）；上传成功与模型实际读取/使用 skill 是不同证据。
- 新执行固定 skill、提示、任务输入、模型配置快照；工作副本后续修改不影响正在执行的版本。
- 远程执行不自动继承依赖本机 env server 的薄壳 skill 或评分流程；对现有场景保留原有契约。

### 3.3 过程、历史与产物

- SDK 的 `chat/subscribe` 作为实时过程接入候选；历史通过 SDK/API 回收，去掉对已删除 CLI 命令的依赖。CLI 执行若需实时观测，须及时取得 session ID 并完成订阅交接；必要时用游标补放，不能漏掉首段事件。
- 保存消息 ID、模型调用 ID、工具调用与返回 ID、事件序号、执行单元、时间、来源、可见性、脱敏与截断状态。实际字段映射通过 beta.41 样本确定。
- 轮次与 react 视图是证据投影，不另造模型回复。下一次模型事件引用前次工具返回；未确认关联须显式标记，不能用相邻时间伪造因果。
- 公开 reasoning、公开计划、普通助手消息、系统摘要分别标识；未提供或未采集的思考不补写。只记录输入上下文中确实可获得的内容。
- 停止与取消作用于远端执行，不能只杀本地等待进程；记录停止请求与最终确认状态，已有过程和产物保留。
- 处理重连、游标补放、重复消息、超大消息切分、并行工具与重试；断点恢复沿用同一 session，重跑创建新的执行身份。
- 产物下载、远端路径与本地落盘继续验证边界；SDK/API 和 CLI 文件传输按能力组合，不假设平台目录与远端 workspace 相同。

## 4. 迁移验收

1. 在隔离测试环境安装精确 SDK，验证当前 adapter 使用的方法签名和事件对象；使用 beta.41 协议样本替换仅覆盖旧 CLI 的测试假设。
2. 验证新会话 → 上传 skill 与输入 → 指定模型执行 → 最终回复 → 产物回收的完整链路。
3. 验证可获取的模型消息、工具调用、真实返回、下一次模型 react；关联可回到来源，缺失信息明确标识。
4. 验证远端停止、失败后回收、重连补放去重、恢复同会话及重跑新会话；不误发重复任务。
5. 继续使用 CLI 时，不再调用 `session history`，且轨迹获取失败会显式反映采集状态。
6. 回归已有场景任务、旧 SDK 恢复、模型选择和 wire 观测；迁移后再开展 Skill Eval 业务模块。
7. 真实预览环境验收记录服务、SDK、CLI 的实际版本，使用专门的小型 skill 和测试附件，不将单元测试通过等同于服务联调通过。

## 5. 后续需要细化的 spec

基于结果微调页已纳入需求：从来源运行的 skill 快照创建独立工作副本，文件树和标签页支持直接编辑 SKILL.md、脚本与模板。实现需区分各文件编辑缓冲、已保存工作副本及运行冻结快照；提供跨文件变更清单，保存、导出、重跑均覆盖整个包，而非仅当前打开的文件。提示和任务物料独立管理，默认复用来源输入并允许单独调整。界面编辑脚本不会自动执行。

- skill、工作副本、版本快照、输入文件、运行记录及人工备注的数据模型。
- skill 导入／编辑／导出、提交运行、停止、历史列表、详情与比较 API。
- 运行状态机、重连协议与事件分页，以及草稿和历史视图之间的导航状态。
- 第一阶段只实现 Blade 的 skill 安装与过程能力；其他智能体 adapter 扩展和跨智能体比较留后续阶段。

已确认每次重跑使用独立会话；同一次运行内支持正常多轮追问、回答与附件，用户主动结束才固定最终结果。技术上须区分断线恢复、运行内续聊、停止生成、结束运行和新会话重跑。
