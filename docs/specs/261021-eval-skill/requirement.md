# Skill Eval 产品需求

版本：v1.2 · 2026-10-22 · 状态：核心产品规则已确认，技术与限额待评审

## 1. 目标

在 OCTAGON 中提供一个 skill 调试工作区，让用户上传或选择 skill，指定智能体与模型，提供提示和输入物料，观察运行结果及过程，再调整 skill 或输入重跑，并比较两次或多次执行。

评估的重点是：skill 的内容如何影响模型理解、智能体行为、工具调用以及最终产出。本期不引入评分体系，用户通过结果、过程证据和人工备注进行判断。

## 2. 已确认的范围

| 范围 | 本期要求 |
| --- | --- |
| 导航 | 新增 `Skill Eval`、`Skill Eval Record` 两个同级入口 |
| Skill 来源 | 支持用户上传自己的 skill，也支持选择已有 skill |
| 输入 | 智能体下拉框仅提供 `blade-agent`；选择模型、上传任务物料、输入提示 |
| 执行 | 独立会话运行，支持多轮文字与附件交互；主动结束运行后固定结果；修改后重跑 |
| 实验 | 用户可新建并命名实验；一个实验绑定一个 skill，包含多次运行 |
| 版本 | 未发布版本可反复保存；发布时使用新版本号另建不可修改的正式版，保留原版本 |
| 调整 | 编辑 skill 正文与随附资源，调整提示，增删替换任务物料 |
| 导出 | 下载当前修改后的完整 skill，也能下载某次运行使用的 skill 版本 |
| 过程 | 查看模型已公开的思考／消息、智能体行动、工具或环境返回、模型对返回的 react |
| 历史 | 当前 skill 的历次运行；全局历史按智能体与模型分组 |
| 比较 | 比较两次或多次执行，查看输入差异、结果及过程 |
| 备注 | 每次运行支持非必填的人工备注，可记录实验细节与评价，支持保存、修改和清空 |

第一阶段仅支持 `blade-agent`。保留智能体下拉框，唯一选项为 `blade-agent`，默认选中；不展示其他智能体或占位选项。模型下拉框继续提供该 Blade 环境可用的模型，允许多次运行比较不同模型或 skill 版本。

首期每次使用一个 skill、一个模型；多 skill 组合和一次批量执行留后续讨论。此限制仅作用于新增 Skill Eval 及其历史／比较，现有平台其他入口的多智能体能力保持原有范围。

## 3. 主流程与页面关系

```text
进入 Skill Eval
  → 上传 skill / 选择已有 skill
  → 查看 skill 详情，创建 / 选择一个命名实验
  → 智能体固定为 blade-agent，选择模型；提示和任务物料均可不提供
  → 运行 → 新建会话与记录，可多轮追问、回答和补充附件
  → 用户结束本次运行 → 固定最终结果 / 完整流程 / 最终产物 / 备注
  → 调整 skill 或输入 → 确认带上全部用户输入与附件 / 重新提供
  → 重跑 → 在同一实验内创建新运行、新会话
  → 勾选两次或多次运行 → 比较
  → 导出需要保留的 skill 版本
```

`Skill Eval Record` 是另一种历史浏览入口：先选择智能体与模型分组，再查看组内运行，最终进入同一个单次运行详情。

### 3.1 实验、运行与对话

- 同一个 skill 可以建立多个实验，用户可命名，例如“销售分析”和“库存分析”；每个实验固定绑定一个 skill，可切换该 skill 的版本、模型和输入。
- 一个实验包含多次运行，每次运行固定一份 skill 内容快照和模型，使用独立 Blade 会话。多轮追问、回答和补充文件都属于当前运行，不创建新的运行记录。
- 模型一轮回复结束不代表运行结束；用户可继续正常交互，点击“结束本次运行”后固定最终结果，不再在该运行追加消息。
- 修改 skill 后必须重跑，新运行仍可归入同一实验；当前会话始终使用启动时的 skill 内容。
- Skill 历史汇总全部实验的运行，可按实验筛选；允许跨实验选择运行进行比较，包括不同 skill 的实验。

### 3.2 Skill Eval 工作区

沿用当前 OCTAGON 的左侧导航、顶部面包屑、语言切换以及深色直角面板样式。

工作区左侧配置下一次运行，右侧展示当前 skill 的详情和历史：

| 区域 | 内容与操作 |
| --- | --- |
| 左侧配置 | 实验选择／新建、智能体、模型、skill 导入入口、可选提示与物料、采集设置、运行／重跑 |
| 右上详情 | skill 名称、来源、用户版本、未发布／已发布状态、修改状态；正文与资源树；编辑、保存、发布、导出 |
| 右下历史 | 当前 skill 各版本与配置的运行列表；查看详情、多选比较、分页、跳转全局历史 |

**右侧默认展示 skill 本身及其运行历史。某次运行的报告、产物与备注在点击记录后的独立详情页展示。**

未导入 skill 时，引导上传或选择；已导入但未运行时，正常展示详情，历史区域提示尚无记录。

## 4. Skill 导入、编辑与导出

### 4.1 导入

- 并列提供“上传 skill”和“选择已有 skill”，没有已有 skill 也能开始使用。
- 支持单个 UTF-8 `SKILL.md`，以及包含 `SKILL.md` 和随附资源的 ZIP 包。ZIP 解包后应只有一个可确定的 skill 根目录。
- 展示导入后的名称、来源、正文、资源清单及校验状态。格式错误、缺少正文、路径不合法或超限时，说明具体原因并允许重新上传。
- 同一管理范围内按名称识别 skill，同名的不同版本归于同一 skill，其历史可按版本筛选；改为未使用的新名称则建立独立 skill 身份。
- 若已有同名 skill，上传内容没有版本信息时，必须提示用户修改为未使用的名称，或填写该 skill 尚不存在的版本号，校验通过后才完成导入。不得自动生成版本号绕过提示。
- 已提供版本号但同名同版本已存在时，同样要求改名或改为未使用的版本号；即使文件内容完全相同，也不覆盖既有版本。
- 首次导入未使用的名称且包内缺少版本号时，默认使用 `0.0.1`；导入版本初始为未发布、可编辑状态，版本号无需带 beta 后缀；之后再上传同名内容必须提供未使用的版本号。冲突时保留暂存文件和输入，不要求重复选择上传包。
- 导入确认展示最终名称、版本和归属 skill；同名新增版本不覆盖旧正文、脚本、工作副本、运行结果或备注。用户版本号与系统不可变内容快照分别展示，内部 hash 或快照 ID 不能代替用户版本号通过重名校验。
- 导入完成后建立工作副本，不直接修改来源目录或已有库中的 skill。

### 4.2 编辑

- Skill 是一个包含 `SKILL.md` 和脚本等资源的文件包。支持直接编辑 `SKILL.md`，以及 Python、Shell、JavaScript、模板、配置和参考文档等文本文件的源内容；脚本不是仅可上传或查看的只读附件。
- 提供文件树和多文件标签页；支持新建、上传、重命名、替换和移除资源，保留相对路径、文本编码及脚本执行权限。二进制资源提供适用格式的预览、替换和下载，不作为文本编辑。
- 显示修改和保存状态，明确“当前工作副本版本”与“最近运行使用版本”。
- 运行或导出时固定当前内容，避免操作过程中版本漂移。历史运行的 skill 内容不随编辑改变。
- 切换 skill、离开页面或重新上传时，处理未保存修改，不静默覆盖。

### 4.3 保存与发布

- 未发布版本（可作为 beta 暂存）允许使用同一版本号反复保存，保存覆盖该版本的当前内容；历史运行仍引用各自的不可变快照，不受覆盖影响。
- “保存”与“发布”是不同操作：发布必须填写该 skill 尚未使用的新版本号，另建不可修改的正式版本，原未发布版本保留且可继续编辑。
- 上传与编辑采用不同冲突规则：上传同名同版本一律拒绝，即使目标是未发布版本；只有在平台内编辑已有未发布版本，才允许原版本号保存。
- 已发布版本不可覆盖。从正式版进入微调时建立独立工作副本，可先编辑、直接试跑；首次保存必须填写未使用的版本号，创建未发布版本。
- 运行与导出无需先保存版本：系统冻结当前全部文件作为不可变快照，不自动更新用户已保存版本。用户点击保存时，才更新未发布版本内容。
- 平台内发布正式版纳入本期；写回外部 skill 库、公开市场发布仍不包含在内。

### 4.4 导出

- “导出当前 skill”：无需先运行，下载当前编辑内容，包含尚未运行的修改。
- “导出本次 skill”：在运行详情和比较列下载该次执行冻结的版本。
- 默认 ZIP 包含 `SKILL.md` 和随附资源，保留相对目录；文件名可识别 skill 与版本／时间。
- 不自动混入任务输入文件、用户提示、运行日志、生成产物或人工备注。
- 导出包可再次导入，正文、资源内容及相对路径保持一致；二进制资源和执行权限的保留需纳入实现验收。
- 导出失败保留工作副本并允许重试；导出操作本身不发起运行。

## 5. 输入与执行

### 5.1 配置输入

- 智能体下拉框只显示并默认选中 `blade-agent`；模型列表来自目标 Blade 环境。无效或不可用的模型不可运行，并说明原因。
- 创建、重跑和比较等相关接口同样限定智能体为 `blade-agent`；不能仅靠前端隐藏其他选项，收到不支持的智能体时应明确拒绝。
- 任务物料单独上传，支持多文件、预览／下载、移除和替换，与 skill 自带资源分开管理。
- 文件展示名称、大小及上传状态；同名文件明确替换或重命名，不静默覆盖。
- 提示提供清晰的输入入口和多行编辑区，用户能看到实际提交的文本。
- 可选项不强制填写；平台能明确判断的必需项缺失时阻止运行并定位。不能假定能从任意 SKILL.md 自动推导全部必需物料。
- 提示和任务物料均为可选，只有 skill 也能运行；不能因没有提示或物料阻止执行。若底层协议需要启动指令，必须显示其内容并与用户提示分开留存，具体文案属于实现评审项。

### 5.2 运行与多轮交互

- 点击“运行”立即创建可追踪记录，每次运行创建全新的 Blade 会话与工作目录，不继承旧模型回复、远端聊天状态或生成文件；重复请求不应创建重复执行。
- 运行前冻结整个 skill、初始提示与物料、智能体、模型和有效采集设置。允许不保存直接试跑，冻结当前编辑内容即可，不强制创建或更新用户版本。
- 运行过程中尽可能保持日常使用 skill 的方式：智能体提问时显示等待用户回答；用户可回答、追加说明和上传附件，模型给出结果后也能继续追问，沿用本次会话。
- 后续用户消息、附件、问题及回答按顺序追加到当前运行记录，不回写初始输入快照，不由平台自动代答；新增物料须先上传成功再提交。
- 模型回复结束进入等待继续，只有用户点击“结束本次运行”才正常结束并固定最终结果。结束后如需继续，应创建新的运行。
- 区分“停止当前生成”与“结束本次运行”：停止作用于远端真实执行，确认后保留可继续交互的运行；结束运行后禁止新消息，等待执行停止／静止并回收最终结果。失败或取消也保留已有证据。
- 显示运行状态、当前活动、等待对象与最后事件时间；执行、采集、产物回收状态独立，不把等待用户回答或连接中断显示为完整结束。
- 刷新或重连恢复同一运行／会话，不重新发送提示；用户离开页面不等于主动结束运行。

### 5.2.1 最终结果

每次运行的结果包含最终结论、实际操作及可观察的副作用影响、最终产物和完整过程。以本次运行结束时的结果为准，不保留各轮结束时的产物副本，也不提供按轮次回退比较。对话与过程事件继续完整保留，不因不保存中间产物而删除历史消息；外部副作用仅展示可观察证据，不承诺自动回滚。

正常运行以用户主动结束后的最终结果作为比较对象；失败／取消记录可展示和比较其已回收结果，但明确标记结果不完整。尚未结束的运行只能实时查看，不作为固定结果进入比较。

### 5.3 微调与重跑

- 用户可调整 skill、提示或物料后重跑，不强制先保存用户版本；每次冻结当前完整内容，创建新的运行与会话。
- 重跑前必须手动确认输入：选择“带上全部用户输入与附件”或“重新提供”，不得静默默认沿用。前者包括来源运行中的初始提示、全部用户回答／追问及上传附件，展示完整清单供确认；后者清空这些输入，提示和物料仍均可留空。
- 旧模型回复、生成产物及旧会话状态不自动作为新输入；带上历史用户回答时显示其原始轮次和问题引用，保留来源，不能冒充本次已发生的问答。
- 重跑前可查看 skill、提示、物料及模型配置相对来源运行的差异。
- 在同一实验创建新运行并关联来源，旧记录、skill 快照、最终结果和备注保持独立；历史导入为其他实验时须遵循该实验绑定 skill 的限制。
- 支持“从此记录继续调整”，复制历史 skill 为独立工作副本。编辑不会热更新来源会话，断线恢复与新运行重跑严格区分。

### 5.4 基于结果微调 skill 页面

从运行详情的“基于结果微调 skill”进入，将该次 skill 快照复制为工作副本。左侧展示来源运行的结果、产物、工具返回与人工备注，右侧以多文件编辑器为主；用户可依据问题修改指令和脚本，而不必离开页面查找原始文件。

- 左侧支持切换运行结果／完整流程／备注，预览历史产物并定位具体调用和返回。来源证据只读，切换证据不丢失文件编辑缓冲。
- 右侧用文件树和标签页切换 `SKILL.md`、脚本、模板等文件；每个文件独立保留未保存内容，并标记相对来源运行的新增、修改、删除或重命名。
- 提供当前文件与来源版本的差异视图，以及整个 skill 包的修改摘要；正文与脚本的改动可同时核对。恢复来源内容时明确作用于哪个文件，不静默丢弃其他修改。
- “保存版本”保存所有改动文件及目录变化，不启动运行；已有未发布版本可原版本号覆盖，来自正式版或无保存目标时要求填写新版本号。
- “试跑／重跑”冻结当前全部文件并确认输入，不要求先保存用户版本；“发布正式版”单独使用新版本号。原运行快照和最终产物不变。
- 默认展示来源 blade-agent 和模型；提示与物料通过重跑确认面板由用户选择带上或重新提供，输入改动与 skill 文件改动分别展示。
- “导出当前 skill”导出完整最新工作副本，包括尚未运行的正文和脚本修改。导出与执行使用一致的冻结内容。
- 显示未保存、保存中、成功或失败；离开页面时处理未保存修改。缺失 SKILL.md、文件无效或上传未完成时定位问题，禁止提交不完整包。
- 编辑脚本不会自动执行代码；实际行为通过后续运行及其过程证据验证。尚无历史结果时仍可编辑 skill，依据区展示相应空态。

## 6. 单次运行详情

从当前 skill 历史或全局历史进入，展示运行 ID、状态、时间、智能体、实际模型、skill 版本及来源运行。

详情提供：

- **运行结果**：运行中的当前回复／临时产物明确标为未固定；结束后展示最终结论、可观察操作／影响、最终产物及预览下载，不保留各轮产物版本。
- **交互区**：未结束时显示对话、待答问题、文字输入、附件上传、停止当前生成和结束本次运行；结束后转只读。
- **完整流程**：运行中的过程及完成后的回看，见第 7 节。
- **输入与交互记录**：初始冻结快照、后续用户消息和附件分开展示，可与当前编辑草稿区分。
- **运行备注（可选）**：每次运行一段独立文本，用于记录实验细节、观察、问题或主观评价；支持事后补充、保存、修改和清空，失败、取消的运行也可备注。
- **后续操作**：基于结果微调 skill（进入专门的多文件编辑页）、导出本次 skill、加入比较、返回 skill 详情或原历史列表。

备注不作为运行、重跑或比较的前置条件，也不计入模型提示或 skill 内容。没有备注时显示“暂无备注”，输入框提示“可记录本次实验的细节、观察或评价”。重跑的新记录默认无备注，不自动继承来源运行的评价；来源备注仍可在微调页作为只读证据查看。保存时显示保存中、成功或失败，失败保留输入并允许重试；切换记录前处理未保存修改，避免丢失或串到其他运行。历史列表展示备注摘要，比较时展示各次独立备注。

**首期适用范围**：读取输入，返回文字结论或生成新的输出文件。文字结论本身可以是有效结果，没有新文件不判为失败。HTTP 查询取数可以作为过程的一部分；以写入外部系统（如提交订单、发消息、更新数据库／HTTP 写接口）或原地修改／删除上传物料为目标的 skill 暂不纳入首期支持与验收，不承诺评估、回滚或比较其实际副作用。需要转换／编辑物料时应输出新的结果文件，原始上传文件保持不可变。

运行配置处常驻展示：“当前支持读取输入、生成文字结论或新文件。暂不支持写入外部系统、原地修改或删除上传物料的 Skill；请使用测试数据，物料修改请输出为新文件。” 运行详情和比较页提供同一范围说明入口。此说明是评测适用边界，执行层的强制限制能力尚待验证，不声称已阻止副作用。若过程实际观察到超出范围的行为，保留证据并标记“超出当前评测范围”，不据此宣称外部效果已验证；不额外重发请求探测效果。文件检查失败显示未能确认，不能伪装成无文件。

耗时、token 和费用只展示实际可获得的数据；未知值标为未提供。产物不能预览时提供文件信息和下载，不显示空白成功。

## 7. 完整流程：模型思考、行动、返回与 react

### 7.1 阅读目标

用户应能回答：模型如何理解任务？智能体做了什么？工具或环境返回了什么？模型收到返回后如何反应、修正并继续？

主阅读结构为：

```text
模型已公开的思考／计划／消息
  → 智能体行动（调用与参数）
  → 工具／环境返回（结果或错误）
  → 模型收到返回后的 react
  → 下一行动或最终回复
```

### 7.2 内容与交互

| 内容 | 展示要求 |
| --- | --- |
| 模型思考／消息 | 区分公开 reasoning、reasoning summary、计划和普通助手消息；保留实际原文与来源 |
| 智能体行动 | 展示实际调用、参数、执行者及状态，区分模型建议与真实执行 |
| 工具／环境返回 | 与调用对应，展示正文预览、错误或退出码；可展开完整已采返回 |
| 模型 react | 展示实际收到返回后的下一次回复、公开思考或直接发起的下一行动，注明关联返回 |
| 实时状态 | 区分模型生成、工具执行、等待返回、停止及连接中断；不把无事件推断成正在思考 |

- 按轮次组织，提供轮次索引；可切换原始时间顺序、搜索消息和参数、展开调用及返回。
- 提供跟随最新事件／暂停跟随。向上阅读时不被新事件强行拉走，并提示新增数量。
- 提供查看本轮模型上下文、原始事件和采集缺口的入口；内容不可得时明确说明。
- react 是下一次真实模型回复；在前轮末尾引用时保持唯一事件身份，不重复计数。
- 并行调用分别配对返回，重试保留每次结果。没有可靠关联时标为关联未确认，不能只凭时间相邻拼成因果链。
- skill 已上传、模型已读取、行为符合 skill，是不同层次的证据，不相互替代。

### 7.3 采集边界

- 只展示模型、智能体及环境实际提供且平台已采集到的内容，不补写私有思考或模型尚未发生的反应。
- 未提供、未采集、脱敏、截断、断流缺段分别说明；完整流程表示已采范围内的完整展示。
- 若后续加入系统摘要，必须标注为系统生成并能追溯原文，不替代实际思考或 react。
- 视图切换与采集设置分开：打开完整流程不重跑，也不会补采旧数据或自动提高采集档位。
- 本功能默认采集可获得的公开思考、工具参数与返回正文，运行前展示生效范围；遵守部署上限和脱敏规则，无法提供的字段明确标记。

示例验收：读文件返回解码错误 → 下一次模型回复决定先检查编码 → 智能体重新读取 → 用户能连贯追溯这次修正，而不是只看到一条“read_file 失败”。

## 8. 运行历史与多次比较

### 8.1 当前 skill 的历史

按稳定 skill 身份展示所有实验、所有版本的运行，可按实验和版本筛选；第一阶段均由 `blade-agent` 执行，允许包含不同模型。列表默认最新在前，显示运行 ID、skill 版本、状态、实际执行配置、时间及查看入口，支持分页与多选比较。

“查看全部运行记录”进入全局历史并携带当前 skill 筛选；切换 skill 同步更新历史范围。

### 8.2 Skill Eval Record

- 一级按“智能体 + provider + 规范化模型 ID”归组，同一组合汇总成一行；第一阶段智能体均为 `blade-agent`，实际主要按模型区分。模型显示别名不能造成错误合并。
- 展示运行数量、最近运行时间与状态；支持智能体、模型、skill、实验、版本、状态和时间范围筛选。
- 点击分组展开或进入二级记录，列出每一次运行及备注摘要、来源关系，支持查看详情与多选比较。
- 返回列表保留筛选、分页、位置和合理的选中状态。历史和运行详情有稳定可恢复的地址。

### 8.3 比较

- 至少选两次，支持三次及更多。可从实验、skill 历史或全局历史发起，支持跨实验和不同 skill；仅比较已结束运行的最终结果，不按对话轮次选择结果。
- 指定一条基准运行，比较 skill 正文和资源、提示、任务物料及执行配置的变化。
- 并排查看最终回复、产物、客观运行信息和各次备注，并可进入对应完整流程。
- 流程分别保持真实事件结构，不假定第 N 个事件语义相同。第一阶段只比较 `blade-agent` 的运行，跨模型比较时突出配置差异。
- 不生成自动得分或获胜者；不支持直接 diff 的产物并排预览或下载。
- 多列在桌面横向浏览；窄屏在基准与当前列间切换，运行标题和身份始终可辨认。

## 9. 数据留存与异常

| 情况 | 要求 |
| --- | --- |
| 草稿继续编辑 | 不覆盖任何已运行快照；相同输入再次运行也生成新记录 |
| 历史文件或来源 skill 被移除 | 已保存的运行输入、skill 内容和产物仍可回看；不能只保存外部路径 |
| 上传中／上传失败 | 展示进度或失败原因，允许重试；未完成时不能提交不完整输入 |
| 已有输入同名 | 明确替换或重命名，不静默覆盖 |
| 执行失败／取消 | 保留已有过程和产物，可备注、调整并重跑 |
| 采集失败／部分采集 | 与执行失败区分，显示具体缺口，不将空数据展示为完整流程 |
| 刷新／断线／事件重放 | 恢复同一次运行，去重事件；不重复提交或丢弃已保存数据 |
| 备注或导出失败 | 保留编辑内容，提示失败并允许重试 |
| 比较项不可访问 | 列出缺失项，保留可访问项；不足两项不能进入比较 |

每次运行保留实验归属、用户版本和准确内容快照、初始及追加用户提示、输入物料、智能体与模型实际配置、来源运行、过程与产物索引、备注及客户端／服务版本。草稿、运行快照、任务输入、skill 资源和输出产物应有清晰边界。

CLI 支持上传 skill、物料并携带提示执行；它不直接对外提供完整实时事件流。完整产品需要把执行与 SDK/API 采集接通，不能以版本升级代替实时采集的实现。具体接入方案写入 [spec.md](spec.md)。

目标是远程服务，新功能不应强依赖远端访问本机 localhost 的场景回调，也不需要为了运行 skill 强行创建评分场景。运行时记录实际版本和会话身份，环境更新后不得仍标记旧版本。

- 尚未完成：本轮版本／实验／交互规则的 Pencil 页面更新（变更清单见 [ui-change-list.md](ui-change-list.md)）、Skill Eval 业务页面与接口、skill 版本与输入存储、提交执行、运行中采集组合、历史和比较功能、指定环境的真实执行联调。

## 11. 已确认决策与剩余实施问题

2026-10-22 已确认：同名新增版本归入同一 skill；未发布版本可原号保存、发布另建新号正式版；新运行独立会话，同一运行内正常多轮交互；默认采集可获得正文；提示与物料均可选；重跑输入需手动确认；用户主动结束后以最终结果比较，不保存各轮产物版本。

以下仅为剩余实施问题，不重新打开上述产品决策：

| 事项 | 需要决定／验证的内容 |
| --- | --- |
| 执行参数 | 结果／流程为视图，多轮交互属于基本能力；是否提供 planning／executing 等额外选项另行评审 |
| 空输入启动 | 核对 Blade 的 skill 启动方式，若协议要求消息，确定可见的系统启动指令，不强制用户填写 |
| 已有 skill 来源（已确认） | 配置服务器只读目录，仅复制导入，不写回来源；不接受客户端任意路径 |
| 容量与资源 | 包大小、文件数、单次生成超时、并发、空闲会话保留和产物回收限制具体值；用户等待时间不可当作模型超时 |
| 发布外部同步 | 本期仅平台内正式版本；是否写回外部库或市场留后续 |
| 重跑消息表达 | 全部用户输入和附件须带上；具体如何传给全新会话、关联旧提问及附件路径需要协议验证，不能重放旧工具调用或模型输出 |

## 12. 首期不包含

自动评分、排行榜、裁判模型、自动选优、自动优化 skill；数据集批量评测与一次批量组合执行；多 skill 组合；多人评论或审批；skill 发布市场。

第一阶段不接入其他智能体，不提供跨智能体比较；多智能体扩展留后续阶段。外部写操作及原地修改／删除输入的副作用评测也留后续；首期不实现通用副作用验证器或回滚能力。
